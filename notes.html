🛠 Galera Cluster 故障修復 SOP

Bootstrap a Galera DB Cluster (SOP)

Node 1 - Set mariadb Environment Variable
GCIS_ID=$(hostname | cut -d'-' -f2) DBAAS_NAME=$(hostname | cut -d'-' -f3) echo ${GCIS_ID}_${DBAAS_NAME}
Node 1 - Step 0: Stop DB service
systemctl stop mariadb-${GCIS_ID}_${DBAAS_NAME}
Node 1 - Step 1: Find which node is most recent node by checking their Galera seqno
/bin/galera_recovery --defaults-file=/u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/mariadb.cnf
Node 1 - Step 2: Ensure New Cluster environment variable is not set
systemctl unset-environment _WSREP_NEW_CLUSTER
Node 1 - Step 3A: Verify
grep safe_to_bootstrap /u01/mydata/${GCIS_ID}_${DBAAS_NAME}/grastate.dat # should return "safe_to_bootstrap: 0"
Node 1 - Step 3B: Start DB (wsrep new cluster)
systemctl unset-environment _WSREP_NEW_CLUSTER systemctl start mariadb-${GCIS_ID}_${DBAAS_NAME}
Node 1 - Step 4: Monitor cluster
watch -n 5 "mysql --defaults-file=/u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/mariadb.cnf -e \"SHOW GLOBAL STATUS LIKE 'wsrep_%'\""
Node 2 - Set mariadb Environment Variable
GCIS_ID=$(hostname | cut -d'-' -f2) DBAAS_NAME=$(hostname | cut -d'-' -f3) echo ${GCIS_ID}_${DBAAS_NAME}
Node 2 - Step 0: Stop DB service
systemctl stop mariadb-${GCIS_ID}_${DBAAS_NAME}
Node 2 - Step 1: Find which node is most recent node by checking their Galera seqno
/bin/galera_recovery --defaults-file=/u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/mariadb.cnf
Node 2 - Step 2: Check seqno (grastate.dat)
#Change value “safe_to_bootstrap” to 1 in file vi /u01/mydata/${GCIS_ID}_${DBAAS_NAME}/grastate.dat
Node 2 - Step 3: Join cluster (after Node 1 is up)
# Ensure safe_to_bootstrap: 1 on Node 2 grep safe_to_bootstrap /u01/mydata/${GCIS_ID}_${DBAAS_NAME}/grastate.dat # >>> should return "safe_to_bootstrap: 1" systemctl set-environment _WSREP_NEW_CLUSTER='--wsrep-new-cluster' systemctl start mariadb-${GCIS_ID}_${DBAAS_NAME}
Node 2 - Step 4: Turn off New Cluster environment variable
systemctl unset-environment _WSREP_NEW_CLUSTER
Witness - Step 1: Stop garbd
#systemctl stop galera-garbd-${GCIS_ID}_${DBAAS_NAME} systemctl stop galera-garbd-
Witness - Step 2: Start garbd (after Node 1 & 2 are up)
#systemctl start galera-garbd-${GCIS_ID}_${DBAAS_NAME} systemctl start galera-garbd-

Manual SST (for Node 2 if join fails)

Step 1: Stop the issue node
GCIS_ID=$(hostname | cut -d'-' -f2) DBAAS_NAME=$(hostname | cut -d'-' -f3) systemctl stop mariadb-${GCIS_ID}_${DBAAS_NAME}
Step 2: Run SST for full sync data
du -sh /u01/mydata/${GCIS_ID}_${DBAAS_NAME} rm -rf /u01/mydata/${GCIS_ID}_${DBAAS_NAME}/* systemctl unset-environment _WSREP_NEW_CLUSTER systemctl start mariadb-${GCIS_ID}_${DBAAS_NAME}

🔍 OS 現地即時效能診斷 (Live Triage - 不留髒檔案)

A1. 初始化環境變數 (查當天用)
export LC_TIME="POSIX"; SARFILE="sa$(date +%d)"
A2. 初始化環境變數 (查指定歷史日期，例如 22 號)
export LC_TIME="POSIX"; SARFILE="sa22"
1. CPU 總體趨勢即時查 (排除單核雜訊)
sar -P ALL -f /var/log/sa/${SARFILE} | grep -E 'all|usr|system' | less
2. Context Switch 執行緒鎖競爭排查
sar -w -f /var/log/sa/${SARFILE} | less
3. 記憶體與 Swap 換頁風險交叉檢視
echo "=== [Memory Usage] ===" && sar -r -f /var/log/sa/${SARFILE} | less echo "=== [Swap Usage] ===" && sar -S -f /var/log/sa/${SARFILE} | less
4. Disk I/O 吞吐與延遲 (自動轉設備名 -p)
sar -d -p -f /var/log/sa/${SARFILE} | grep -v -E '0.00 0.00 0.00' | less
5. Run Queue 與系統 Load Average 趨勢
sar -q -f /var/log/sa/${SARFILE} | less
6. 網路流量即時查 (看 Galera 複製/備份頻寬)
sar -n DEV -f /var/log/sa/${SARFILE} | grep -E 'IFACE|eth|bond' | less
🔥 終極：指定歷史故障時間點精準打擊 (範例: 14:10-14:40)
sar -P ALL -f /var/log/sa/${SARFILE} -s 14:10:00 -e 14:40:00 | grep 'all' sar -d -p -f /var/log/sa/${SARFILE} -s 14:10:00 -e 14:40:00 | grep -v '0.00' sar -q -f /var/log/sa/${SARFILE} -s 14:10:00 -e 14:40:00

🔄 MariaDB 版本升級 SOP (AP / AA)

變數初始化

GCIS_ID=$(hostname -s | awk -F'-' '{ print $2 }') DBAAS_NAME=$(hostname -s | awk -F'-' '{ print $3 }') old_version=10.11.15 new_version=10.11.17

📌 AP 節點升級流程

1. Pre-check
/var/opt/gcis/upgrade/main.upgrade.sh -precheck -function upg_mariadb_ap -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db
2. Upgrade
/var/opt/gcis/upgrade/main.upgrade.sh -upgrade -function upg_mariadb_ap -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db
3. Post-check
/var/opt/gcis/upgrade/main.upgrade.sh -postcheck -function upg_mariadb_ap -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db

⚠️ AA 節點升級流程（需特別注意順序）

1. Pre-check (AA)
/var/opt/gcis/upgrade/main.upgrade.sh -precheck -function upg_mariadb_aa -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db
2. Upgrade (AA)
/var/opt/gcis/upgrade/main.upgrade.sh -upgrade -function upg_mariadb_aa -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db
3. Post-check (AA)
/var/opt/gcis/upgrade/main.upgrade.sh -postcheck -function upg_mariadb_aa -prop /u01/mycnf/${GCIS_ID}_${DBAAS_NAME}/operation.properties -cfg /tmp/dbaas_mariadb_${old_version}_to_${new_version}_upgrade.cfg -hosttype db

⚠️ 注意： AA 節點必須先執行完前一步（尤其是 Pre-check）才能執行 Upgrade！
